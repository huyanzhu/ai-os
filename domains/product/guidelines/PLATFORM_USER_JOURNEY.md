## 一、平台一句话

> 帮助普通用户，以最低总成本解决真实问题。

用户不是来买软件的。用户是来解决问题的。
平台的价值不是"接单"，而是帮用户搞清楚两件事：

1. 我真正的问题是什么？
2. 谁最适合帮我解决？

### 核心信念

> **平台不是为了留住用户，而是帮助用户解决问题。**

因此：

- 推荐其他平台，不是失败。
- 用户选择自己做，不是失败。
- 用户去了 Marketplace，也不是成功。

真正的成功标准只有一个：

> **用户的问题被确认了。**

---

## 二、用户三种状态

用户来到平台时，只可能处于三种状态：

| 状态 | 用户心里想的 | 对应入口 |
|------|------------|---------|
| 迷茫 | "我不知道怎么办" | **我有问题** |
| 明确 | "我知道要做什么" | **我要开发** |
| 有能力 | "我可以帮别人" | **我是开发者** |

这三个入口不是功能分类。是**用户心智状态的分类**。

## 三、完整用户旅程

### 路径 A：迷茫 → 发现 → 解决

```
用户进入官网（Landing）
  │
  │  看见：一句话说明平台能做什么
  │  看见：三个入口按钮
  │  感受：这里能帮我吗？
  │
  ├─ 点击"我有问题"
  │
  ▼
Consultant（Discovery 模块）
  │
  │  看见：对话界面
  │  输入：一句话描述（"我想做个小程序"）
  │
  │  AI 开始追问（Hypothesis Engine）
  │  看见：AI 说"我觉得你的问题可能是……对吗？"
  │  选择：是 / 差不多 / 不是
  │  循环：直到 AI 确认真正的问题
  │  感受：原来我的问题不是这个……
  │
  │  Problem 确认
  │
  │  看见：AI 输出三个方案
  │
  ├─ 选方案一"自己完成"
  │       │
  │       │  看见：怎么做 + 工具 + 教程 + 时间 + 成本 + 难度
  │       │  追问："具体怎么做？""在哪下载？"
  │       │  AI 继续指导（同一 Session，同一 Problem）
  │       │  用户完成 → Session 自然结束
  │       │
  │       ├─ 用户引入新 Problem
  │       │       │
  │       │       ▼
  │       │   输入框上方出现提示：
  │       │   "建议开启新的咨询。"
  │       │   [开始新的咨询] [继续当前咨询]
  │       │   （非强制，AI 根据上下文判断）
  │
  ├─ 选方案二"去其他平台"
  │       │
  │       │  看见：推荐平台 + 链接 + 预算 + 周期
  │       │  看见：一段可直接复制发给外包的需求描述
  │       │  追问："怎么联系他们？""沟通时注意什么？"
  │       │  AI 继续指导（同一 Session，同一 Problem）
  │       │  用户完成 → Session 自然结束
  │
  └─ 选方案三"帮我找人"
        │
        │  看见：直接按钮 → Marketplace
        │  不解释，不推销
        │
        ▼
    Marketplace
        │
        │  看见：你的需求已发布
        │  看见：匹配中的开发者
        │  看见：报价、开发者信息
        │  选择：接受谁的报价
        │
        ▼
    Workspace
        │
        │  看见：项目进度、对话、交付物
        │  验收 → 付款
        │
        ▼
      结束（双方互评）
      
      用户回到 Consultant 页面
        │
        │  Session 标记为 Complete
        │  用户可以继续问同一 Problem 的后续
        │  如果引入新 Problem → 输入框上方提示
```

### 路径 B：明确 → 直接发布

```
用户进入官网
  │
  ├─ 点击"我要开发"
  │
  ▼
Task 发布页
  │
  │  输入需求描述（背后仍是 Consultant 静默分析，但不追问）
  │  看见：AI 自动整理的结构化 Task
  │  确认发布
  │
  ▼
Marketplace → Workspace → 结束
```

### 路径 C：有能力 → 接单

```
用户进入官网
  │
  ├─ 点击"我是开发者"
  │
  ▼
Provider Center
  │
  │  注册 / 登录
  │  填写能力标签 + 履历
  │
  ▼
项目大厅
  │
  │  浏览 Task 列表
  │  筛选：类型、预算、领域
  │  报价 / 接单
  │
  ▼
Workspace → 交付 → 验收 → 互评 → 结束
```

## 四、模块边界（Frozen）

每个模块有明确的**入口条件**和**出口条件**。

### Landing

| 属性 | 值 |
|------|-----|
| 入口条件 | 用户访问官网 URL |
| 出口条件 | 用户点击三个入口之一 |
| 职责 | 一句话说明平台价值 + 三入口分流 |
| 不属于它的 | 对话、追问、任务管理 |

### Consultant

| 属性 | 值 |
|------|-----|
| 入口条件 | 用户点击"我有问题" |
| 出口条件 | Problem 确认 + 用户选择方案 |
| 职责 | 把模糊需求变成确定的问题 |
| 不属于它的 | 找开发者、管理项目、接单 |
| 基本单元 | **Session**（一次 Problem Discovery 生命周期） |
| 结束条件 | Problem 确认 + 三个方案输出 + 用户选择 |
| Session 规则 | 一个 Session = 一个 Problem。同一 Problem 的后续追问（"怎么做""怎么下载"）属于同一 Session，不提示新建 |
| 新 Problem 检测 | 由 AI 根据上下文判断用户是否引入了新 Problem，不使用关键词或固定规则触发 |
| 提示位置 | 当 AI 判断新 Problem 出现时，提示出现在**聊天输入框上方**（非页面顶部），与 GPT 额度提示位置一致 |
| 提示文案 | "建议开启新的咨询。继续使用当前咨询，可能会让顾问把两个需求混在一起。[开始新的咨询] [继续当前咨询]" — 非强制，用户可选择继续 |

### Marketplace

| 属性 | 值 |
|------|-----|
| 入口条件 | Consultant 方案三确认 / "我要开发"发布 |
| 出口条件 | 用户接受报价 → Workspace / 用户取消 |
| 职责 | Task 发布、开发者浏览、报价、匹配 |
| 不属于它的 | 追问需求、项目执行、支付 |

### Workspace

| 属性 | 值 |
|------|-----|
| 入口条件 | Marketplace 匹配成功 |
| 出口条件 | 交付验收 → 互评 |
| 职责 | 协作、交付、验收、支付 |
| 不属于它的 | 匹配开发者、发现需求 |

### Provider Center

| 属性 | 值 |
|------|-----|
| 入口条件 | 用户点击"我是开发者" |
| 出口条件 | 注册完成 → 进入项目大厅 |
| 职责 | 开发者注册、能力档案、履历、状态 |

```
Landing ──→ Consultant ──→ 三个方案

本轮 Sprint 的完整范围：

```
Landing 页
  │
  │  用户看见：
  │  ┌─────────────────────────────────┐
  │  │                                 │
  │  │    AI Product Platform          │
  │  │                                 │
  │  │    帮用户以最低总成本            │
  │  │    解决真实问题                  │
  │  │                                 │
  │  │    ┌──────────────┐             │
  │  │    │  我有问题     │  ← 本轮重点 │
  │  │    └──────────────┘             │
  │  │    ┌──────────────┐             │
  │  │    │  我要开发     │  ← 灰色     │
  │  │    └──────────────┘             │
  │  │    ┌──────────────┐             │
  │  │    │  我是开发者   │  ← 灰色     │
  │  │    └──────────────┘             │
  │  │                                 │
  │  └─────────────────────────────────┘
  │
  ├─ 点击"我有问题" → 进入 Consultant
  │
  ▼

  │
  │  已有的 Hypothesis Engine 对话
  │  本轮需要对齐：
  │    - 3-4 个选项，最后一个永远是"都不是"
  │    - 对话上限 ≤ 15 轮

**本轮不做的：**

- Marketplace（灰色按钮，点击提示"即将开放"）
- Provider Center（灰色按钮，点击提示"即将开放"）
- 登录 / 注册（保存时再谈登录）
- "我要开发"入口的实际功能（灰色按钮）

## 六、各模块之间的连接点（Frozen）

```
Landing → Consultant : 用户点击"我有问题"
Consultant → 结束    : 用户选方案一或方案二
Consultant → Marketplace : 用户选方案三 + 确认发布

Landing → Marketplace : 用户点击"我要开发"（跳过 Consultant）

Landing → Provider Center : 用户点击"我是开发者"
```

连接点是接口。每个模块只需要知道：
- 谁把我唤醒的？
- 我把用户交给谁？

## 七、North Star（北极星指标）

> **3 分钟内帮助用户找到真正的问题，而不是立即解决问题。**

这不是验收标准。这是整个平台的方向判断——任何功能、任何改动，用这句话检验：

> "这个改动，是帮用户更快找到问题，还是在分散注意力？"

---

## 八、用户感受目标

这不是量化的 KPI。是每个模块结束时，用户心里应该浮现的那句话。

| 模块 | 用户应该感到 |
|------|------------|
| Landing | "这里可以帮我。" |
| Consultant | **"终于有人真正理解了我要解决的问题。"** |
| Consultant | **"原来我的问题是这个。"** |
| Marketplace | "有人能帮我解决。" |
| Workspace | "不用操心，都在推进。" |

注意：Consultant 的目标感受**不是**"这个 AI 好厉害"、也不是"它给了我好多方案"。而是用户对自己问题的重新认识。

如果用户离开 Consultant 时没有这种感受——说明 Hypothesis Engine 没有真正工作。用户只是被套话，没有被理解。


## 九、Frozen（产品宪法）

以下内容已冻结。这不是"当前设计"，这是"产品不会改的东西"。
后续 Sprint 可以讨论实现方式，但不再讨论这些条目本身。

| 冻结项 | 内容 |
|--------|------|
| 产品定位 | AI Product Platform — 帮用户以最低总成本解决真实问题 |
| 三入口 | 我有问题 / 我要开发 / 我是开发者 |
| Consultant 边界 | Discovery，不负责 Delivery |
| 基本单元 | **Session**（一次 Problem Discovery 生命周期）。一个 Session = 一个 Problem |
| Session 结束条件 | Problem 确认 + 三个方案输出 + 用户选择 |
| 三方案顺序 | 自己完成 → 去其他平台 → 平台帮你找开发者 |
| 三方案输出模板 | ① 怎么做+工具+教程+时间+成本+难度 ② 平台+链接+预算+周期+可复制需求描述 ③ 直接按钮→Marketplace |
| 新 Problem 检测 | 由 AI 根据上下文判断，不使用关键词或固定规则 |
| 新 Problem 提示 | 输入框上方，"建议开启新的咨询"，非强制（用户可选择继续） |
| Marketplace 定位 | 人与需求的连接，不是 AI 接单 |
| Landing 定位 | 平台入口，不承担业务逻辑 |
| 模块连接点 | Landing → Consultant →（结束 / Marketplace） |
| 本轮开发范围 | 只实现 Landing + Consultant，其余入口灰色 |
| North Star | 3 分钟内帮助用户找到真正的问题，而不是立即解决问题 |
| 成功标准 | 用户的问题被确认了，不是用户留在了平台 |
| 核心信念 | 平台不是为了留住用户，而是帮助用户解决问题 |

## 十、本轮禁止讨论

以下话题在本轮 Sprint 中**禁止展开**。
不是因为不重要，而是因为讨论它们会分散注意力，导致 Landing 一行代码没写。

| 禁止讨论 | 原因 |
|---------|------|
| Marketplace 怎么匹配 | 下一阶段的事 |
| Workspace 怎么协作 | 下一阶段的事 |
| AI-OS 自动化 | AI-OS 有自己的节奏，不等平台 |
| Agent 能力 | Consultant 不是 Agent |
| Provider 细节 | 还没到开发者端 |
| Payment / 担保 | V2 的事 |
| 登录 / 注册 | 首次需要保存状态时再谈 |

**规则**：Sprint 内，只允许讨论本轮目标。其他想法记录到 Backlog，不展开。
