# Self-Verification 自我验证技能包（无复核者生存技能）

**解决**："这里没有 code review、没有 QA、没有旁人在看每一步——我唯一的保险就是自己证明自己做对了。"（产品开发 Agent 2026-08-06 声明）

**对应角色**：solo 开发者（无复核者环境）+ 质量保障（provider 测试账号补充闭环视角）。

**核心洞察**：无复核者环境里，"我宣布完成"和"我已证明完成"是两件事——中间差的正是 Self-Verification 这个能力。它不是一条技巧，是**一个能力的三个面**：开工核状态（防在旧世界上干活）、交付验资金（防功能通但钱没动）、断言先算账（防把产品判错）。加上真实路径（防只测接口）和闭环收口（防下游没收口）。

## 五模块（= 三个声明的整合 + 调研补充）

### ① 开工先核状态（声明 2）
- 每轮开工读最新状态：验收清单/backlog/状态文件，不等提醒、不假设它们没变
- 缺失行为实证：验收清单 12:23 更新 12:36 才知道；backlog 失真靠人问才去清
- **关联**：skill_pack_direction（定位）→ 状态新鲜是方向的地基

### ② 断言先算账（声明 3，已收编 assert_recalc）
- 写断言前纸面独立过账（每笔列全、独立求和），断言值永不来自被测代码中间结果
- 实证：两次把产品判成 bug（漏算 ¥80 / 漏算 +80），产品全对、心算错了，白耗两轮

### ③ 交付后验资金流（声明 1 + 声明 4 融合）
- 修完任何带钱的功能，**自己把钱走到账看一眼**——不等人来报、不等用户质疑
- 实证：P0（99c12b76 验收完成但 ¥100 没结算、接单方实收 ¥0）是用户生命周期采样发现的，不是自验发现的
- **关联**：debug_reconciliation（读数据层还原）+ closure_verify（闭环收口）

### ④ 真实路径 + 闭环收口（声明 1/4/5）
- 真实路径：主动走"最顺手的捷径路径"（realpath_test，已收编）
- 闭环收口：切到对方侧走完下游动作 + 数据层不变式断言（closure_verify，本次新收编）
- **调研升级**：不变式写成**属性断言**（fast-check property-based testing，随机验证旁路），路径自动化用 Playwright

### ⑤ 环境给复核（调研新增，另一条路）
- 不只是"自己更自律"——还有"环境给复核"这条路：**PR-Agent**（14k⭐）开源 AI 代码审查（/review /improve /test），GitHub Action 集成
- 意义：MIRROR 研究的落地——外部脚手架 > 自我认知；给 solo 开发者一个"假的复核者"比纯靠自觉可靠

## 检查清单（宣告 done 前自测）
- [ ] 开工核过最新状态了吗？（不等提醒）
- [ ] 带钱的改动，钱自己走到账看过一眼了吗？（不等人报）
- [ ] 断言是独立核算的吗？（不心算、不抄被测代码）
- [ ] 最顺手的捷径路径走过了吗？（不只接口全绿）
- [ ] 切到对方侧确认链路收口了吗？（数据层不变式过没过）
- [ ] 有没有可用的 AI 复核者（PR-Agent 等）？（环境给复核，不只自己扛）
