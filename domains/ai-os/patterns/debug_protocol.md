# 科学调试协议（复现优先 → 单假说证伪 → 证据报告）

**来源**：外部 Skill（Human 提供，Evolution Intake #2）——adityaarakeri/senior-agent-skills 的
`debug-protocol` SKILL.md（2026-08-23 HTTP 200 逐字下载，原文存
`evolution/intake/debug-protocol/SKILL.md`）。按 Skill Fusion 先例（2026-08-05：9 个外部 Skill
→ domains patterns 进 experience_push 检索源）收编为 V2 pattern。

**解决**：原因未知的 bug / 报错 / 崩溃 / 回归 / flaky / 性能失败——把每一步调试变成
"确认或否决一个解释"的证据。防两个最贵的失败模式：凭直觉反复改（每次改多个变量，
永远不知道哪一步生效）；把"貌似合理的理论"说成"已确认诊断"。

## 什么时候用 / 不用
- **用**：stack trace、输出不对、间歇性失败、环境不一致、同一 bug 反复修不好。
- **不用**：根因已确定、任务只是实现已知修复——那是 TDD 场景，走 `testing-tdd`
  （Prove-It 先测复现），不重跑诊断。

## 协议（AI-OS 上下文映射）
1. **选模式**——仅诊断（不改生产代码、不实现修复）/ 诊断+修复（诊断完成后，
   把确认行为交给 TDD 回归测试再实现）。
2. **先复现**——最小安全确定性测试/脚本/trace/命令。未经明确授权不对生产或私密数据做实验。
3. **读完整首条错误**——捕获精确输入/输出/版本/配置/环境/时间戳/关联 ID。
4. **偶发降噪**——重复运行/固定种子/受控时钟/资源限制/隔离环境；考虑竞态、超时、
   重试、部分失败、环境对等。
5. **单假说**——陈述一个可证伪假说："X 发生是因为 Y"。跑最便宜的能证伪它的实验：
   一次只改一个变量，读实际值而非推断值。
6. **插桩纪律**——临时、受控、无密钥；交付前移除并确认仓库状态。
7. **回归二分**——`git bisect` 只在干净 disposable worktree 或明确批准后使用；
   记录起始状态，离开前必 `git bisect reset`。
8. **追源头**——把非法状态追溯到其产生处，区分根因与故障表象位置（表象位置 ≠ 根因）。
9. **三连拒即停**——三次假说被否决后停止改代码：基于证据重建系统模型、总结尝试、
   请求缺失的人工/环境输入。

## 证据报告（输出形态）
报告：复现方式 / 支持的根因 / 已否决假说 / 影响范围 / 置信度 / 下一个安全边界。
**不得把貌似合理的理论四舍五入成已确认诊断。**

## 与既有调试簇的关系（互补，非重复）
- `debug_reconciliation`（端到端对账读数据层）= 本协议内的**一个具体取证技巧**
  （UI/数据不符时读权威数据层还原代码路径）。
- `testing-tdd` = 本协议的**修复侧承接**（外部原文的 tdd-loop 在 V2 无运行时，
  映射为 testing-tdd 的 Prove-It：先测复现，再实现——不新建机制）。
- `closure_verify` / `assert_recalc` / `realpath_test` / `silent_false_green` =
  验证侧族（宣告 done 前的收口、断言独立核算、真实路径、测试假绿陷阱）。
- `environment_first`（WFI-005 三级诊断）= 工具层故障的排查顺序（先权限 → 工具边界 →
  系统性），与本协议叠加使用。

## 检查清单（诊断中自测）
- [ ] 我复现了吗（最小确定性复现，不是"大概会这样"）？
- [ ] 我陈述的是一个可证伪假说吗（不是现象复述）？
- [ ] 这次实验只改了一个变量吗？
- [ ] 我区分了根因和表象位置吗？
- [ ] 证据报告能独立支撑结论吗（没有"我觉得应该就是"）？
